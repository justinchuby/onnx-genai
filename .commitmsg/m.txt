feat(pipeline): a generic node-executor seam in the interpreter

B2 checkpoint 1 of the workflow-runtime unification: the interpreter gains a
seam for steps the runtime implements, so a fused decode session can become a
*node executor the interpreter drives* rather than a second loop beside it.

A workflow declares what happens at each step. Most steps are ONNX graphs the
package ships; some are steps the runtime implements — an autoregressive decoder
driven by a session that owns paged KV on device, or the token policy that
scores logits and decides when generation ends. A package states those as
`implementation: binding` with a contract id. Until now the interpreter answered
a binding by copying same-named ports, which is fine for a pass-through and
useless for a step with an implementation.

`WorkflowNodeHost::execute_contract_node` is that implementation point. The
interpreter still owns everything that makes it a *workflow*: `continue_when`,
`max_iterations`, `carried`, `termination`, the emits, and the SSA environment.
The host advances exactly one node. A host that owned the loop would be the
second runtime this work exists to remove.

**Fail-closed.** A binding declaring a contract that no host implements is now an
error. Previously it fell through to the port copy, which would define the
outputs with the wrong tensors and let a declared step silently not happen —
indistinguishable from success at the API. Bindings without a contract keep the
pass-through, which is what the existing workflow fixtures use.

The host is threaded as `Option<&mut dyn WorkflowNodeHost>` through
`run_workflow_node`'s five recursion sites and reaches the interpreter through
`execute_retained_with_host`; `execute_retained` passes `None`, so every
existing caller is unchanged.

Two unit tests pin the seam: a host declining a contract it does not implement
(so the interpreter can report it rather than silently doing nothing), and a
host defining the declared outputs (so "the executor ran" is distinguishable
from "the interpreter fell through to a port copy").

`WorkflowNodeRequest` carries a scoped `dead_code` allowance: this checkpoint
defines the seam and its dispatch, and the first non-test implementor is the
autoregressive-decode host in the next commit. The allowance is on the struct
alone so it cannot hide anything else, and it goes away with that commit.
