fix(metadata): a package with many graphs is not a single decoder

Auditing our published Hugging Face packages for the migration workstream found
a defect no in-repo fixture had the shape to catch.

`justinchuby/sensenova-u1.5-8b-mot-onnx-canonical` declares 187 components, 186
of them ONNX graphs. Exactly one — its text head — carries `token_ids`/`logits`
roles, because that is what a text head is. `is_single_decoder_workflow` asked
`sole_decoder_component(..).is_some()`, which is the question "*which* component
is the decoder" and is deliberately answerable for composite packages: that
resolver exists precisely so a vision-language package can name its decoder.
Reusing it as "is this package *only* a decoder" answered yes for that package,
and the loader would have handed 186 graphs to the fused single-graph executor
that can run one. Every VLM classified the same way — the repo's own
`onnx_genai_workflows/vlm` fixture included.

The predicate now asks what the phrase means: does this workflow execute **one**
ONNX graph? Components the runtime implements (`binding`, such as the token
policy) are not graphs and do not count. Pinned by
`a_multi_component_package_is_not_a_single_decoder` over five fixtures spanning
both answers.

**`validate_metadata` gains `--metadata-only` and `--shape`.** Full package
validation requires every artifact to be present, which is right for a runtime
and useless for a publisher: the package this bug was found in is 49 GB, and
requiring its weights before its metadata could be checked would mean nobody
checks metadata before uploading it. `--shape` reports single-decoder vs
composite vs no-workflow, which is the triage question when migrating a fleet —
and is how the misclassification became visible.

**New: `docs/genai/CANONICAL_SINGLE_DECODER_PACKAGE.md`.** The authoring
reference the HF workstream needs: the shape in one picture, the five rules that
are easy to get wrong (roles name ports; state is declared once; a fixed-capacity
cache is not also growing pairs; the token policy is a binding; declare your
capabilities), what "single decoder" means to the runtime and why it is narrower
than "has a decoder", and the convert/validate/republish workflow.

**Published-package audit — no metadata replacement required.** Recorded in that
document with revisions and a reproduction recipe:

* `justinchuby/sensenova-u1.5-8b-mot-onnx-canonical` @ `541afaea1` — already
  canonical, validates against this branch, correctly composite.
* `justinchuby/gemma-4-e2b-it-onnx` @ `9bcf2cb1c` — 13 variants of
  `genai_config.json`, a foreign format the importer converts. Unaffected.

Third-party models we consume are not ours to republish and ship formats this
change does not touch.

Verified: 73/73 engine targets; 57/57 across metadata, scheduler, ort,
genai-config, model-package, preprocess, CLI, C API and server — exit 0; fmt;
clippy `-D warnings`; goldens byte-identical.
