feat(metadata)!: retire model.io; a single decoder is an ordinary workflow

A single decoder was the last package shape with its own representation. It
declared `model.io` — a second, parallel way to state a graph ABI — and the
runtime had a matching second path to read it. This removes the shape, not the
capability: a decoder is now a `pipeline.workflow` with one ONNX component,
declared with exactly the constructs a multi-component workflow uses.

**The block is gone from the schema.** `ModelCapabilities::legacy_io` and its
accessor are deleted, `decoder_io()` resolves from `pipeline.workflow` and
nowhere else, and `decoder_io_is_legacy()` — which existed to tell an operator
*which* of two sources answered — has nothing left to distinguish. The
regenerated JSON schema is 527 lines smaller. In-memory lowering
(`metadata::canonical`, `Engine::install_canonical_workflow`) is deleted too:
there is no compiler, no fallback, and nothing synthesized at load.

**A package that still declares it is refused, with the conversion named.**
`ModelCapabilities` does not deny unknown fields, so `serde` would have dropped
the key and left the package failing later with a puzzled "declares no
workflow". `parser::reject_retired_model_io` recognizes the retired shape for
the sole purpose of explaining it; it is the one place the old spelling appears
and it never produces a value.

**Every maintained package is converted.** `metadata::decoder_workflow` is the
inverse of the existing recognizer: it turns a decoder ABI into an authored
workflow whose port roles, `state_service` group and generation loop the
recognizer reads back. The two are only trustworthy as a pair, so round-trip
equality is asserted — including a 12-layer case, because state ports live in a
`BTreeMap` and a naive conversion silently binds layer 10 between 1 and 2.
`migrate_model_io` is the offline tool the rejection names; it validates before
writing and reads the graph for real port contracts rather than guessing a
state tensor's rank, which is a lie that fails at load for whichever package
happens to disagree. All 14 fixtures are converted with it.

**`genai_config.json` still imports** — it is a foreign producer's format, and
converting it is the whole point of an importer. It now states its result as a
workflow like everything else, so the real-model corpus keeps working with no
`model.io` anywhere.

**Two latent bugs surfaced and are fixed at the cause:**

* The recognizer reported a fixed-capacity cache as *both* a static-cache ABI
  and growing past/present pairs. `resolve_kv_layers` reads the absence of
  pairs as "this cache does not grow", so an authored static-cache workflow
  would have had a paged bridge built over a buffer that never grows and
  addressed with the wrong discipline. A scatter group now yields the
  static-cache ABI and nothing else, and ownership is derived from whether the
  component *writes* attention state rather than from the pair list — which
  keeps read-only KV sharers `Shared`.
* "Is this a pipeline?" was answered independently in three places (engine
  loader, server state, CLI/server multimodal). Now that a decoder declares a
  workflow, "declares a workflow" stopped distinguishing them and they
  disagreed. `is_single_decoder_workflow` is the one recognizer all three ask.

`RuntimeCapabilities::default` gains the structural workflow capabilities,
because a runtime that executes workflows implements them by definition — and
otherwise every load would warn until operators learned to ignore the warning.

Verified: 73/73 engine targets (native-backend); metadata, ort, genai-config,
model-package, CLI and C API green; server 239/240 with only the pre-existing
`fim_stream_returns_headers_before_generation_finishes` load-flake, which
passes 3/3 in isolation.
