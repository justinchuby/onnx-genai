## The dependency

Every gate this PR adds lands in `rust-quality`, including `Test ORT-backed workspace crates`. `Rust quality` is currently **red on `main`** for an unrelated reason — #2056 left a call site behind `#[cfg(feature = "native-backend")]` on the old `SessionPlacement` API, and that job reports the first failure it hits.

So a red `Rust quality` on this PR right now says nothing about whether the new ORT step passes. **#2115** fixes the inherited break; this should be refreshed onto it before anyone reads its CI as a verdict on this change.

I have deliberately **not** armed auto-merge here, for a reason specific to this PR: it moves six crates' tests into a required job, so if any of them is red, merging turns `main` red for every open PR rather than for this one. That is the opposite of the failure mode #2015 is about, and it is not a decision to make on a queued signal. Local pre-flight of exactly that step is running; I'll post the result either way.

## What I did verify, on the merged tree

The script's own gates and — more to the point — its falsifiers:

| invocation | exit | expected |
|---|---|---|
| `workspace_test_packages.py self-test` | 0 | pass |
| `workspace_test_packages.py verify` | 0 | pass |
| `workspace_test_packages.py verify-required-tier` | 0 | pass |
| `verify --simulate-missing onnx-runtime-session` | **1** | **must fail** |
| `verify-required-tier --simulate-dropped-lane ort-backed` | **1** | **must fail** |

Both negative controls fail on demand, so neither gate is passing by seeing nothing. That matters more than the three passes: `verify` and `verify-required-tier` are both the shape that goes green when it finds nothing to check.

The three passes are also not stale — they derive their package set from the workspace as it is now, and `main` has churned a lot today (#2034, #2056, `cf23d0e7e`). `cargo-args ort-backed` still resolves to the intended six: `onnx-genai`, `-capi`, `-cli`, `-engine`, `-ort`, `-server`.
