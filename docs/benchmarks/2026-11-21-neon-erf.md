# Native ARM64 Erf and exact GELU absorption

The native ARM64 route previously mapped a double-precision scalar routine over
each element. It now evaluates the existing MLAS-derived Erf polynomials with
four-lane NEON and fuses exact GELU around that result. On this Apple M1 Max
experiment, it reduces wall time by 14.45–18.46× for Erf and 12.05–14.47× for
exact GELU versus that former body. **MLAS remains faster in most measured
cells. This is not family graduation or removal of the reference dependency.**

## Implementation and numerical contract

The port shares `erf_c` with AVX2, including its split at 0.921875, saturation
clamp at 3.925, Estrin evaluation, and reduced-range exp coefficients. The
crate's independent `MLAS_LICENSE` retains the complete upstream MIT notice.
There is no runtime call or link to MLAS on the native route.

Dispatch requires runtime NEON detection and the existing `SIMD_MIN_LEN = 32`
threshold. Short slices retain the scalar implementation. The choice is made
once on the full slice; chunks and tails use the same vector arithmetic.
Remainders use four initialized stack lanes and copy only their live prefix.
NaNs are masked before range reduction and explicitly quieted from the original
input to preserve sign/payload. Erf preserves signed zero and saturates infinities;
exact GELU preserves the existing `Gelu(-Inf) = +0` policy.

BiasGelu uses the same algorithm after an in-register f32 bias addition. Narrow
rows prepare cyclic four-lane bias phases in a fixed stack buffer; wider rows
load contiguous bias vectors and bound their partial tails. No full intermediate
or retained allocation is introduced. BiasGelu performance was not measured here.

This intentionally changes long ARM64 slices from the scalar oracle's rounded
answers to the existing vector approximation contract, as already happens on
AVX2. It does not claim byte identity with the former scalar answers. Tests
retain the existing Erf/GELU bounds, plus a tighter direct NEON Erf check:

- 400003 grid points, both signs and neighbors of branch/saturation/underflow
  boundaries, 100003 pseudorandom f32 bit patterns, and explicit nonfinite values:
  500040 inputs total. Against the existing f64-to-f32 oracle, worst Erf absolute
  error is `5.960464477539063e-8`; worst GELU error divided by `max(1, |x|)` is
  `1.1920391808974291e-7`. The existing bounds remain `3e-7` and `4e-7` respectively.
- Native-entry tests cover lengths 0–96 at all four input offsets, with output
  sentinels and numerical witnesses distinct from the scalar body. Those
  witnesses make dispatch evidence specific to the caller, even if another test
  increments the diagnostic counters.
- Actual native scheduling is compared bitwise with serial execution; nested
  Rayon calls at widths 1/2/4/8 must suppress another split and preserve bits.
  Bias widths 1–13 include partial rows and the short-slice seam.
- The optional differential test now classifies vector availability per family:
  ARM64 Erf/GELU keep the strict one-ULP differential checks; Tanh/Sigmoid retain
  their independent scalar-oracle contract. No accuracy guard was relaxed.

The code-generation locality guard remains intact: generic scheduler
instantiations stay inside `simd_activations.rs`, including the historical
scalar controls used by the diagnostic.

## Measurement scope

Measured source: `25dd39033592a6d2af58c8bbde6173f586ec38f6`. Apple M1 Max,
10 physical/logical CPUs, 32 GiB RAM, macOS 27.0.1, rustc 1.98.0 / LLVM 22.1.8.
Cargo's optimized MLAS lib-test artifact (`opt_level=3`, debug assertions and
overflow checks off) is bound to its exact executable by the runner; the existing
single-codegen-unit crate override is retained. Source/executable/runner hashes,
compiler metadata, exact test inventory, child resource/load receipts, and the
[compressed Cargo receipt](2026-11-21-neon-erf/cargo-build.jsonl.gz) are preserved
with the [measurement metadata](2026-11-21-neon-erf/metadata.json).

Four arms share one process and the same inputs, buffers, iteration counts, and
scheduling policy: former scalar body, native NEON, native A/A, and explicit
MLAS reference. The scalar control reproduces the old element loop in the
original scheduler module; it is test-only. All arms warm up and pass full-buffer
oracle/hash checks before timing. Native test-hit counters remain enabled, so
these are instrumented kernel-call measurements, not exact production latency.

Three sweeps rotate native pool widths 1/4/8 and case/arm order. Each cell has
21 samples per arm, with rotating arm order, over lengths 32, 257, 4096, 65537,
and 4194307, for Erf and exact GELU, in serial and normal-runtime modes.
Inputs permute a finite `[-6, 6]` grid even at the smallest length. A batch has
`clamp(1048576 / n, 1, 8192)` calls; durations are divided by that batch count
before medians and ratios are computed. Input preparation, full oracle/hash
validation, logging, and the lightweight output-token read occur outside each
timing window. The token checks three output positions; it is not a full hash.

**15120 timed samples, 720 full-buffer validations, and 180 cells are retained.**
Each native A/A ratio is median(native) / median(native A/A); all fall within
**0.99443–1.00991**, passing the predeclared 0.95–1.05 repeatability band. No rows
were removed. Repeatability is a necessary check, not proof of machine isolation.

Normal-runtime mode calls the native task runtime outside Rayon. Every
validation checks the caller's dispatch counter and actual worker-task counts.
At length 4194307, widths 4/8 require worker participation; width 1 and all
shorter cases correctly stay inline. A configured budget is therefore not
mistaken for proof of parallel work. Output digests agree across widths and
modes for each arm, including native A/A equality.

The runner holds `/tmp/onnx-genai-hostlock-darwin.flock` over the entire sweep;
children retain the descriptor if the parent dies. Nine children exited zero,
total wall time 142.853 s. This is a shared desktop with background activity and
no affinity or foreign-core attribution. The advisory lock and per-child load
receipts do not prove exclusive CPU use. Linux admission/host monitoring, other
ARM64 CPUs, x86 execution, CUDA, ORT host-pool execution, and end-to-end models
were not measured.

Only `Instant` wall durations support the comparisons. Child `wait4` CPU/RSS
receipts are provenance, not per-kernel CPU-cost evidence. The unresolved
[CPU accounting boundary finding](https://github.com/justinchuby/onnx-genai/blob/9efb4ab8c4a424a636cec29568b2136592a2d6f5/docs/benchmarks/2026-11-21-cpu-clock-scope.md)
is not bypassed by these latency results.

## Results and remaining gap

Ranges below span all three sweeps, both execution modes, and all three budgets
at each length. A ratio above one favors native; below one favors its comparator.
Every contributing cell passed native A/A.

| Operation | Elements | Scalar-before / native | MLAS / native |
|---|---:|---:|---:|
| Erf | 32 | 14.45–14.62 | 0.916–0.923 |
| Erf | 257 | 17.36–17.44 | 0.879–0.883 |
| Erf | 4096 | 18.33–18.46 | 0.885–0.890 |
| Erf | 65537 | 18.37–18.43 | 0.885–0.893 |
| Erf | 4194307 | 17.69–18.41 | 0.862–0.892 |
| Exact GELU | 32 | 12.05–12.17 | 1.119–1.124 |
| Exact GELU | 257 | 13.73–13.86 | 0.857–0.875 |
| Exact GELU | 4096 | 14.09–14.42 | 0.830–0.848 |
| Exact GELU | 65537 | 14.40–14.46 | 0.858–0.878 |
| Exact GELU | 4194307 | 14.32–14.47 | 0.913–0.972 |

At 4194307 elements, serial native medians are about 4.74–4.75 ms for Erf and
5.83–5.84 ms for GELU. Normal-runtime native medians at width 4 are
1.263–1.267 ms / 1.519–1.521 ms respectively, and at width 8
0.648–0.658 ms / 0.780–0.785 ms. These are kernel-call latencies with the scope
above; they do not establish model throughput or CPU savings.

The port closes the large scalar implementation gap, but the local MLAS
comparison still rejects graduation: Erf is slower at every measured length,
and GELU beats the reference only at length 32. Plausible next mechanisms to
investigate include explicit NaN masking overhead and loop scheduling/unrolling
versus the MLAS vector implementation. These are hypotheses, not measured
attributions. Preserve payload semantics, accuracy, and A/A controls when testing
them; the optional reference stays available meanwhile.

## Reproduction

Build before taking measurements, preserving Cargo's JSON receipt:

```sh
cargo test -p onnx-runtime-ep-cpu --release --features mlas --lib \
  --no-run --message-format=json-render-diagnostics > /tmp/neon-erf-cargo.jsonl
```

Select the lib-test executable from its `compiler-artifact` record (not an old
cached filename), then run in a fresh output directory:

```sh
python scripts/bench_neon_erf.py run /tmp/fresh-neon-erf \
  --binary /absolute/path/to/release/lib-test-executable \
  --cargo-receipt /tmp/neon-erf-cargo.jsonl
python -O scripts/bench_neon_erf.py analyze /tmp/fresh-neon-erf
python -O scripts/bench_neon_erf.py analyze docs/benchmarks/2026-11-21-neon-erf
```

The Darwin ARM64 runner refuses a dirty/untracked measured source, an incorrect
optimized MLAS artifact, a vacuous exact selector, an existing output directory,
or lock contention. Raw [compressed samples](2026-11-21-neon-erf/samples.csv.gz)
and [per-cell results](2026-11-21-neon-erf/results.json) allow reanalysis without
the executable. The reader verifies identities and batches, not only row count;
full output digests, native A/A tokens, worker participation, oracle bounds,
complete repetitions/arms, and saved medians/ratios are checked under `-O` too.

## Validation receipts

At measured source `25dd39033592a6d2af58c8bbde6173f586ec38f6`, the complete
native debug library suite passed 1935 tests (18 ignored), and the optimized
MLAS library suite passed 1956 (30 ignored). Both held the shared host lock.
Strict all-target Clippy passed in both feature configurations; formatting,
whitespace and dispatch/platform checks also passed. No cross-hardware execution
coverage is inferred from compilation or these counts.

The [reader controls](2026-11-21-neon-erf/reader-controls.json) reject corrupt raw
bytes, duplicate identities, an invalid width with unchanged row count, a wrong
batch, a missing full validation, absent worker participation, inconsistent
native A/A full hashes, and changed saved medians. These controls are separate
from the performance A/A measurements; no raw timing rows were discarded.
