fix(ort): put the lease in the header, and govern by default

Two blocking findings from review.

**G2 was weakened, not preserved.** The previous commit replaced the side
table with a header holding the *size*, and called try_claim/release directly.
That is a convention, not an invariant: a future early return leaks budget,
and a duplicate free subtracts usage belonging to other allocations because
the ledger saturates rather than validating ownership. I had claimed this was
"preserved structurally", which was wrong.

The header now holds the MemoryLease itself. It is 40 bytes and the header is
64, asserted at compile time rather than discovered as a heap overwrite. Free
reads the lease out, which moves ownership, so Drop returns the bytes exactly
once -- the same guarantee the table gave, with none of its cost. Verified by
mutation: wrapping the lease in ManuallyDrop on the free path turns two tests
red.

**Governance was still opt-in, which was the whole point of the exercise.**
SessionOptions::default() now sets session.use_env_allocators. Without it a
session silently builds its own allocator, so a registered governor reports
zero forever and the budget is decorative for every ordinary session. It costs
nothing when no allocator is registered: ORT falls back exactly as before. The
control test now opts *out* explicitly, which is what a caller wanting ORT's
own allocator must do.

Also from review:

The session test's comment claimed it asserted peak usage; it sampled the
budget once after construction and discarded the run's result. It could not
distinguish "inference allocated through us" from "inference failed
immediately". Added a monotonic `total_count` and asserted it moves across the
run -- which promptly failed, because the run *was* failing on a missing input
and allocating nothing. The test now builds inputs from the model's own
signature and requires the run to succeed.

Added the two tests the review found missing: the allocation-failure rollback
path (claim succeeds, system allocator refuses, budget must come back), and
that writing a block's full extent does not reach into its own header.

Still open and acknowledged: the benchmark behind the arena decision is a warm
single-threaded loop. It does not measure fragmentation over a long run, cold
page faults, RSS, or contention across ORT's intra-op threads. "Nothing left to
win" is too broad a claim for it to support, and flipping this default in
anger deserves a real decode loop first.
