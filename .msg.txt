feat(cli): rich REPL editor, declarative command registry, stats by default

Phase 1 of the REPL redesign in docs/research/cli/05-repl-redesign.md.

The REPL was a plain line loop: a >>> prompt, read_line, and hard-coded
command handling with a hard-coded /help that could drift from reality.
No editing, no history, no completion.

Adds a rich TTY input path built on reedline: multiline input, cursor
movement, persistent file-backed history, bracketed paste, and Tab
completion. Commands now come from a declarative registry that drives
parsing, /help generation, and completion from one source, so help text
cannot go stale. Argument completion is live rather than static -- /ep
completes the providers actually available in this build, /backend
completes auto|ort|native, /model completes filesystem paths.

Per-turn stats are now on by default for interactive TTY sessions, which
is the developer-facing default the CLI charter asks for; run --no-stats
opts out and /stats still toggles at runtime.

The terminal model is deliberately the inline viewport rather than a
full-screen alternate screen. Native scrollback and terminal-native copy
are features for a tool whose output gets pasted into issues, benchmarks
and traces, and the alternate screen would cost both.

Everything above is gated on stdin AND stdout being a TTY, resolved once
in repl_input_mode. Any pipe keeps the previous read_line loop, with
stats off, byte-for-byte. That is what protects the repl_e2e.rs contract
tests, which drive the REPL with piped scripts and only started running
in CI with #284.

reedline was verified to share crossterm 0.29.0 with ratatui rather than
pulling a second incompatible version into the process.
