### 2026-08-24T12-23-44: Slice 7D — route-residency production binding builder + EP install/drain seam

**By:** Copilot
**What:** Slice 7D route-residency production binding (RouteResidencyBoundary construction/installation)
**References:** #1810, Slice 7C PR #2007 (`b37810abb`), #1922 producer, #1971 consumer, #1854 lifecycle

**Why:** Slice 7C shipped a *reachable* boundary caller (`ExecutionProvider::consume_route_residency_at_boundary` at `Executor::finish_device_validation`) driving an installed `RouteResidencyBoundary`, but production installed nothing. Slice 7D adds the production *binding* path so the merged live caller has something to drive when the feature is enabled:

- **Property-based builder** `build_route_residency_boundary(graph, residency, sources, catalogs, allocators, pools, …)` in `ep-cuda/route_residency.rs` constructs a binding from `expert_weight_groups(graph)` — the typed (`LazyWeightBoundary::for_op`) discovery already in ep-api. No model/layer/op-name allowlist. It only *binds* existing authorities (residency/catalogs/allocators/pools); it maps nothing and owns no new allocator. Pure `validate_route_residency_binding` splits discovery/validation from GPU construction so it is CPU-unit-testable.
- **Typed fail-closed rejects** `RouteResidencyBindingReject` (NoExpertGroups / MultipleBanksUnsupported / NoTelemetrySource / MissingCatalog / MissingAllocator) — every path installs nothing and carries the reason. No silent partial binding.
- **CUDA-EP install/drain seam** `try_install_route_residency_binding(...) -> RouteResidencyInstallOutcome` (GateDisabled / OffloadDisabled / Rejected / Installed) and `drain_route_residency_boundary()`. Default-off gate is checked *first*: disabled installs nothing and creates no telemetry/policy work. Single binding authority per EP/request/device. Drain is wired into `ExecutionProvider::shutdown` (teardown) before residency retirement.
- **Diagnostics** extended with `installs`/`declines`/`last_install_reason` so install outcomes are observable (the reachability counter the wiring tests assert on).

**Boundary decisions / deferred prerequisites (disclosed, not faked):**

1. **Single-source binding vs multi-QMoE-layer models.** `RouteResidencyBoundary` holds exactly one `RouteTelemetrySource`; the EP holds one `Mutex<Option<Arc<…>>>`. The builder therefore binds exactly one discovered expert group and returns `MultipleBanksUnsupported { groups }` for multi-bank graphs rather than silently covering one. Multi-bank binding (a registry of per-node bindings) is a deliberate later slice.
2. **No fully-wired session-build install call yet.** `try_install_route_residency_binding` is the production seam, but it is not yet *called* from `InferenceSession::build`/executor build, because production has no live artifacts to supply it: (a) `acquire_routed_residency` still "always proves whole-bank today, because no QMoE/BlockQuantizedMoE kernel surfaces `selected_experts` to the host", (b) the EP does not retain per-bank `WeightRegionCatalog`/`CudaVmmAllocator`/`PhysicalHandlePool` maps, and (c) route telemetry sources are session/`KernelCache`-owned, not EP-owned. Wiring the call before real sources exist would install nothing or a whole-bank-only binding. This mirrors how 7A/7B/7C shipped reachable seams ahead of the artifacts that feed them.
3. **No live atomic hot/cold transition from real routing is possible yet** for the same reason as 2(a); the GPU tests drive the transition through a controllable `RouteTelemetrySource` double (a compile-time assertion proves the real `QMoEKernel` satisfies the same trait), exactly the precedent set by the Slice-7B/7C consume tests.

**Validation:** 7 CPU unit tests (discovery + every typed reject) + 4 new GPU tests through the production caller: builder→install→fire→drain from graph discovery; `try_install` fail-closed installs nothing on a non-authority EP (GateDisabled/OffloadDisabled); `try_install` on an offload-authority EP typed-rejects a dense graph and installs+fires a real binding for a two-bank QMoE graph; and a host-only ON-vs-OFF per-boundary overhead micro-measurement (empty-window steady-state path): OFF ≈75 ns, ON ≈376 ns, delta ≈0.30 µs/boundary on an idle A100 — within the ≤2 µs design intent. No full-model or tok/s claim. Default-off; no BC shim (only additive APIs, so no in-repo callers changed). fmt + clippy (`-D warnings`, gpu-tests) clean; 583 ep-cuda lib tests + 9 route-residency GPU tests pass.
