## 2026-08-17 — PR #1139 merged: gate/up SwiGLU decode occupancy-raise default-ON

PR #1139 squash `0636a759` merged Luv's occupancy-raised symmetric RMS-fused gate/up SwiGLU decode GEMV (kernel+test `11a01fae`, default-ON flip `cfc5e812`) behind `ONNX_GENAI_GATEUP_OCC`; it is **byte-identical by construction** and default-ON (mirrors `GATEUP_VEC`/`GEMV_PIPELINE`; `=0` forces non-occ for A/B). Mechanism: add `_vec_occ` siblings of the two SYMMETRIC RMS-norm-fused `_vec` entries whose ONLY source difference is `__launch_bounds__(256, 8)` (plus the symbol name). That caps register allocation at exactly 32 regs/thread (65536/(256×8)=32, no spill), letting 8 blocks co-reside = 100% theoretical occupancy. Bodies are character-for-character identical to their `_vec` parents; the identical instruction stream, fp16 FMA/accumulate order, RMS reduction, and SwiGLU epilogue live in the shared template — `__launch_bounds__` constrains only register storage placement, not source semantics.

Diagnosis (ncu `--set full`, 14b symmetric int4): the default `_vec` kernel was latency-bound and warp-starved — 40 regs → 62.2% achieved occupancy (75% theoretical, register-limited), dominant stall Short Scoreboard ≈51% (warps waiting on the inner-loop staged-activation LDS in `permute_activation_f16x8`). The lever is more resident warps to hide shared-load latency, not fewer instructions (that was #1137). OCC=1: regs 40→32, theoretical occ 75%→100%, achieved 62.2%→81.7%, DRAM 29.7%→32.9%, isolated kernel 57.5µs→54.0µs (−6.2%).

**Symmetric-only.** Routing: `occ = !has_zp && gate_up_occ_enabled()` → `_vec_occ`; asymmetric `_zp` inputs select the existing `_zp` kernel first (it runs at 48–56 regs; forcing 32 would spill and regress — no `_zp` occ variant). `_vec_occ` kernels only exist on the RMS-norm-fused decode path, so OCC is a no-op/fall-through for non-RMS and M>1 rows. `#1137` bias-fold and this occupancy raise are **complementary** — the default-ON `_vec` carries the bias-fold, and `_vec_occ` = `_vec` + launch_bounds, so OCC=1 gets both fewer instrs AND more warps.

Rachael 🟢 APPROVE (default-ON SAFE): `_vec_occ` wrapper bodies character-for-character identical to `_vec` parents after the signature — same template instantiation, same args; no math/reduction/accumulation-order change; dispatch symmetric-only; argmax/tie-break untouched. Reran targeted CUDA on idle GPU0: `gate_up_swiglu_vec_is_bit_identical_to_scalar` 1/1, `gate_up` suite 10 passed / 3 ignored. Non-blocking: the broad test comment slightly overstates `_vec_occ` coverage (only exercised for eligible M=1 RMS rows) — Luv tightened the wording in the default-ON flip.

Wallace GREEN (independent detached worktree `.worktrees/wallace-gateup-occ` @ `11a01fae`; did NOT reuse Luv's GPU; interleaved A/B 5 rounds pinning idle H200 GPU5/6): byte-identity **0.000% divergence over 300 greedy tokens on BOTH qwen2.5-14b and qwen2.5-7b** — decisive gate PASS. Perf: 14b OCC=1/OCC=0 median 171.19/166.82 = **1.026x (+2.6%)**, every round OCC=1 wins (5/5, min-OCC1 168.46 > max-OCC0 168.29) — confirms Luv's +2.4%; 7b flat (ratio 0.9996, ±0.2% noise, no regression — 7b GEMV is not occupancy-bound at that size). The occupancy raise pays off exactly where predicted (14b, GEMV-dominant, Short-Scoreboard-bound) and is inert on 7b. This is the largest single-kernel byte-identical decode win landed so far (vs #1137's ~+0.8%).

Next lever (Luv, dispatched off origin/main incl. `0636a759`, fresh worktree; HOLD lifted post-merge): the kernel is still Short-Scoreboard-bound even at 82% occupancy — all 8 warps in a block redundantly re-permute the SAME staged activation each K-tile. ## 2026-08-17 — MLP down-proj occupancy shelved: byte-identical, spill + no-conversion NO-GO

Luv's `squad/down-occ` branch at `393b162d` ported the #1139 `__launch_bounds__(256,8)` recipe to block-32 MLP down-projection GEMV behind default-OFF `ONNX_GENAI_DOWN_OCC`, adding `_down_occ` / `_down_c4_occ` / `_down_c2_occ` siblings for symmetric int4 while leaving asymmetric `_zp` untouched. Correctness was proven by extending `fp16_down_projection_is_bit_exact_to_staged_kernel` to force c2/c4/c8 via `ONNX_GENAI_DOWN_COLS`; all three `_occ` arms produced 0-bit equality vs the staged reference.

Perf is **NO-GO / SHELVED / NOT MERGED**. On the dominant grid-2560 qwen2.5-14b down launch, achieved occupancy rose **66.5%→87.3%** and theoretical occupancy 75%→100%, but duration stayed flat **22.62→22.59us**, DRAM stayed flat **38.1%→38.6%** (~1.83→1.85 TB/s), and Long Scoreboard worsened **9.62→11.49 cyc/issue**. The 32-reg cap forced registers/thread **39→32** and created **245,760 local-memory spill requests** (baseline 0). End-to-end A/B confirmed the no-go: base won **5/5** rounds, median **167.56 vs 166.15 tok/s** for OCC (−0.8%, worst −2.7%).

Both kill-switches fired: (1) the down body is heavier than gate/up (4× `permute_activation_f16x8`, COLS accumulates, and `warp_sums[8][COLS]` shared reduction), so the 32-reg occupancy cap spills and adds local-memory latency; (2) even with higher occupancy there is no conversion because down is already nearer bandwidth (~38–40% DRAM) and occupancy is not the residual bottleneck. The `(256,6)` fallback is useless because it permits 48 regs and the kernel already uses 39, leaving the same 6-block / 75% theoretical limit as baseline. Lesson: launch-bounds occupancy only converts when the kernel fits the register cap spill-free **and** is truly occupancy-starved, not already near-bandwidth. Luv pivoted to the q/o `_pipe` occupancy lever (14.7% share, 59% occ, lighter body, better spill-free odds).
