### 2026-07-29: Work-stealing pool requires no admin privilege
**By:** Deckard
**What:** The elevation blocker was a Windows launch-time filename heuristic, not pool code and not MLAS init. Reproduced with `threadpool_dispatch-b0949055e59bd258.exe`: CreateProcess failed before `main` with Win32 native error 740 / `ERROR_ELEVATION_REQUIRED` ("The requested operation requires elevation."). Renaming the same binary to `pool_microbench_probe.exe` launched at Medium integrity, while copying the safe bench to `threadpool_dispatch_probe.exe` reproduced error 740.
**Why:** `dispatch` contains the installer keyword `patch`, so Windows Installer Detection/UAC can classify the unsigned benchmark under `target\` as an installer/patcher and require elevation. The shipped pool is pure std thread/atomics/spin/park and uses no privileged API. MLAS ARM64 init already avoids the privileged `ID_AA64ISAR0_EL1` register read and uses `MLAS_CPUIDINFO::HasArmNeonDot()`; `cargo test -p mlas-sys float_kernel_matches_detected_isa --lib --release` and `cargo run -p onnx-genai-cli -- --help` both launched at Medium integrity. Keep benchmark executable names free of installer keywords (`setup`, `install`, `update`, `patch`, including substrings like `dispatch`).
