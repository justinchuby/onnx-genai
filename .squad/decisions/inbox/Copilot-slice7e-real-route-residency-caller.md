### 2026-08-24T13-40-00: Slice 7E — real EP-owned route producer, retained bank artifacts, and wired model-build install seam

**By:** Copilot
**What:** Slice 7E route-residency real caller (remove the "zero-real-caller" limitation left by Slice 7D)
**References:** #1810, Slice 7D PR #2046 (`01ed02092`), #1922 producer, #1971 consumer, #1854 lifecycle

**Why:** Slice 7D shipped the production *binding builder* + CUDA-EP install/drain seam, but explicitly deferred three prerequisites (7D decision record §2): (a) route telemetry sources were session/`KernelCache`-owned, not EP-owned; (b) the EP retained no per-bank expert artifacts; (c) no session/model-build call constructed/installed the binding. Slice 7E removes all three, so the merged live boundary caller has a **real** producer and a **real** build-time install path when the feature is enabled — with no test double for the producer.

- **Goal 2 — real EP-owned producer (fully real).** New `RouteTelemetrySourceRegistry` (`Mutex<HashMap<NodeId, Arc<QMoEKernel>>>`) in `ep-cuda/kernels/qmoe.rs`. `QMoEFactory::create` now builds an `Arc<QMoEKernel>`, registers that *executing* instance by `node.id`, and returns a thin `SharedQMoEKernel(Arc<QMoEKernel>)` wrapper so the `KernelCache` runs the exact same `Arc` the EP observes (kernel `execute`/telemetry are `&self` interior-mutable). The registry is created by the EP ctor and threaded through `build_cuda_registry_with_metrics`, so the same `compile_all` pre-warm that materializes the static decode graph's kernels registers them EP-side before decode capture. New EP accessors `route_telemetry_sources()` / `route_telemetry_producer(node_id)`. No controllable test double.
- **Goal 1 — retained per-bank artifacts (real).** The EP retains the property-discovered `Vec<ExpertWeightGroup>` (bank node identity + member `ValueId` ranges) in a `Mutex<Option<Arc<…>>>` after weights finalize, exposed via `retained_route_residency_artifacts()`. Populated only on the enabled discovery path; `None` by default; cleared on drain.
- **Goal 3 — wired model-build install seam (real).** `install_route_residency_after_build(&graph) -> RouteResidencyInstallOutcome` runs real discovery over the finalized graph + real EP-owned producer sources, retains artifacts, then probes the physical prerequisite. It is invoked from the **real production build path**: `Executor::build_with_cuda_requirement` calls the new default trait method `ExecutionProvider::install_route_residency_boundary_after_build(&graph)` once, after `compile_all`+`size_buffers` and before any decode; `Drop for Executor` calls `drain_route_residency_boundary_on_teardown()`. `plugin_provider` delegates both to its inner EP.
- **No-BC breaking change (as directed).** Two new trait methods were added as **default** no-ops (object-safe; CPU/plugin/hetero inherit them) rather than required, because the existing required `consume_route_residency_at_boundary` has impls across hetero/plugin/tests — making these required would ripple without benefit. All in-repo callers/tests updated atomically; no compatibility shim.

**Central honest-scope decision (disclosed, not faked): the shipped enabled path is a typed *decline*, not an install.** A real hot/cold transition on real weights is blocked by an out-of-scope residency refactor: production `CudaWeightResidency` admits every paged weight into **one shared** `CudaVmmAllocator` reservation (`PhysicalAdmission.allocator`) with per-key stable-VA slots (#716), keyed by page-key — **not** a dedicated per-bank reservation. The coarse plan (`apply_coarse_residency_plan` → `transition_granule_range`) addresses each bank at **catalog-relative** offsets, which only a per-bank dedicated reservation (base at the bank's first byte) satisfies. So `install_route_residency_after_build` fail-closes with a new typed reject `RouteResidencyBindingReject::NoPerBankReservation { value }` (probed via the new `CudaWeightResidency::coarse_route_bank_reservation`, which returns `None` on the shipped shared-reservation layout) rather than remapping the wrong bytes. This is **capability-gated, not theater**: the same seam, over the same retained artifacts + real producer sources, constructs and installs a real binding the moment a residency provides per-bank reservations. Per the repo honesty guardrail, no live-transition test with a hidden double was fabricated for this slice.

**The disclosed residual (the one remaining bridge):** admit routed expert banks into **dedicated per-bank VMM reservations** (plus per-bank `WeightRegionCatalog`/pool retention) in `CudaWeightResidency`, after which `coarse_route_bank_reservation` returns `Some` and this seam installs+fires a real binding end-to-end from real routing. This is a residency-layer change, deliberately out of Slice 7E's scope, and must avoid the BQMoE-ABI files currently rebasing.

**Default-off guarantee (strengthened):** the gate-off branch of `install_route_residency_after_build` is now a **pure inert early return** — it retains nothing, installs nothing, arms no telemetry, and records no diagnostics (not even a decline counter). The executor still calls the hook unconditionally, but on the shipped default it touches no shared EP state.
