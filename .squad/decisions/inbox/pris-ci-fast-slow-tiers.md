### 2026-07-27: Split CI into fast and slow tiers
**By:** Pris
**What:** CI is split into a fast PR tier and a slow/full tier. Fast PR CI keeps formatting, clippy, publish-order/profile/platform/dispatch checks, uninstrumented Linux x86_64 offline-crate tests, Linux/Windows x86_64 `onnx-genai-cli` build/test/e2e, and the Windows `onnx-runtime-loader` path-safety tests. Slow CI runs on push to `main`, nightly schedule, manual dispatch, and PRs carrying the `ci:full` label; it adds coverage uploads (`offline`, `mlas`, `cli-ort-linux`, `cli-ort-windows`), the full Windows x86_64 offline-crate suite, Windows ARM64, macOS arm64, CUDA compile lanes, and `audit`.
**Why:** Coverage instrumentation was the largest new cost (+9:06 on CLI Windows, +5:00 on Rust Windows, +3:11 on Windows ARM64) and has low marginal correctness signal on every PR. Windows x86_64 remains in the fast tier only for the CLI lane because Justin develops on Windows and today's Windows misses were contract/e2e and ORT DLL-loading issues. Platform coverage should be spent where platform differences actually bite in this repo: CLI, ORT loading, filesystem, terminal, and dynamic linking boundaries. Pure-Rust offline logic crates still run on Linux per PR and move to Windows in the slow tier, except when the platform difference is the subject of the test. The `onnx-runtime-loader` rooted-path test is that exception: Windows path semantics are the risk being tested, so it stays in fast CI.
**Trigger decision:** Justin was away, so I chose the slow-tier triggers in his absence: merge to `main`, nightly, manual dispatch, and `ci:full` label on an open PR. He should revisit this if he wants a different slow-tier cadence.

**Branch protection:** `gh api repos/justinchuby/onnx-genai/branches/main/protection/required_status_checks` returned `Branch not protected`, so no required status check rename trap was present at implementation time.
**Windows offline-test audit:** I searched the offline crates for Windows-specific cfg tests before removing the Windows offline suite from PRs. The meaningful Windows-only offline test is `onnx-runtime-loader::pathsafe::tests::rejects_rooted_path` (`#[cfg(windows)]`); because it tests Windows path semantics directly, it now runs in the fast Windows lane via `cargo test --locked -p onnx-runtime-loader pathsafe`. I did not find additional `#[cfg(windows)]` tests in the offline suite. I did find Windows-specific implementation code in `onnx-runtime-tracer` and `onnx-runtime-ep-cpu::decode_affinity`, plus ORT/CUDA Windows cfg code outside the offline crate set; those are not additional Windows-only offline tests being silently dropped from PRs.
**CI enforcement observation:** No required status checks are configured, and the active `main` ruleset only enforces deletion/non-fast-forward/linear-history. That means this rename/split is not a required-check trap, but it also means CI is not enforced for merges; Justin should decide whether to add required checks separately.
**Label path:** The `ci:full` label exists in GitHub, and both `ci.yml` and `audit.yml` include `pull_request` `labeled` triggers with slow-tier job conditions checking that label. Justin verified this end to end on PR #340: adding the label started slow CI run https://github.com/justinchuby/onnx-genai/actions/runs/30345861354 and audit run https://github.com/justinchuby/onnx-genai/actions/runs/30345861425 alongside the fast lane.
**Visibility:** Slow-tier post-merge failures surface as failing `CI`/`Rust security audit` Actions runs on `main` and as nightly failures. Concurrency still keys non-PR CI by SHA, so a later push does not cancel or mask a completed/active post-merge signal.

**Skipped matrix-name fix:** GitHub evaluates a job-level `if:` before expanding `strategy.matrix`, so fast-tier skips of slow matrix jobs reported raw names like `Rust coverage (${{ matrix.name }})`. I replaced the conditionally gated slow matrices in `ci.yml` with explicit per-platform jobs (`Rust coverage (Linux x86_64)`, `Rust coverage (Windows x86_64)`, `Rust slow platform (...)`, `CUDA compile (...)`) so skipped checks have stable, branch-protection-safe names. `miri.yml` has no matrix and no matching issue. A repo-wide scan found similar job-level gated matrices only in release/manual workflows (`publish.yml` and `wheels.yml`), not in PR CI; I left those release workflows untouched for this CI-tiering PR.
