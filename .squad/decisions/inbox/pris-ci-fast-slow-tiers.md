### 2026-07-27: Split CI into fast and slow tiers
**By:** Pris
**What:** CI is split into a fast PR tier and a slow/full tier. Fast PR CI keeps formatting, clippy, publish-order/profile/platform/dispatch checks, uninstrumented Linux x86_64 offline-crate tests, and Linux/Windows x86_64 `onnx-genai-cli` build/test/e2e. Slow CI runs on push to `main`, nightly schedule, manual dispatch, and PRs carrying the `ci:full` label; it adds coverage uploads (`offline`, `mlas`, `cli-ort-linux`, `cli-ort-windows`), the full Windows x86_64 offline-crate suite, Windows ARM64, macOS arm64, CUDA compile lanes, and `audit`.
**Why:** Coverage instrumentation was the largest new cost (+9:06 on CLI Windows, +5:00 on Rust Windows, +3:11 on Windows ARM64) and has low marginal correctness signal on every PR. Windows x86_64 remains in the fast tier only for the CLI lane because Justin develops on Windows and today's Windows misses were contract/e2e and ORT DLL-loading issues. Platform coverage should be spent where platform differences actually bite in this repo: CLI, ORT loading, filesystem, terminal, and dynamic linking boundaries. Pure-Rust offline logic crates still run on Linux per PR and move to Windows in the slow tier.
**Trigger decision:** Justin was away, so I chose the slow-tier triggers in his absence: merge to `main`, nightly, manual dispatch, and `ci:full` label on an open PR. He should revisit this if he wants a different slow-tier cadence.

**Branch protection:** `gh api repos/justinchuby/onnx-genai/branches/main/protection/required_status_checks` returned `Branch not protected`, so no required status check rename trap was present at implementation time.
**Windows offline-test audit:** I searched the offline crates for Windows-specific cfg tests before removing the Windows offline suite from PRs. The meaningful test that stops running per PR is `onnx-runtime-loader::pathsafe::tests::rejects_rooted_path` (`#[cfg(windows)]`); it is filesystem/path handling and therefore adjacent to the platform-risk area, but it is covered by the slow Windows suite. There is also Windows-specific implementation code in `onnx-runtime-tracer` and `onnx-runtime-ep-cpu::decode_affinity`, but I did not find additional `#[cfg(windows)]` tests in the offline suite.
**CI enforcement observation:** No required status checks are configured, and the active `main` ruleset only enforces deletion/non-fast-forward/linear-history. That means this rename/split is not a required-check trap, but it also means CI is not enforced for merges; Justin should decide whether to add required checks separately.
**Label path:** The `ci:full` label exists in GitHub, and both `ci.yml` and `audit.yml` include `pull_request` `labeled` triggers with slow-tier job conditions checking that label. I did not open a PR per coordinator instruction, so live label-on-PR observation is left for the coordinator-created PR.
**Visibility:** Slow-tier post-merge failures surface as failing `CI`/`Rust security audit` Actions runs on `main` and as nightly failures. Concurrency still keys non-PR CI by SHA, so a later push does not cancel or mask a completed/active post-merge signal.
