### 2026-07-27: Split CI into fast and slow tiers
**By:** Pris
**What:** CI is split into a fast PR tier and a slow/full tier. Fast PR CI keeps formatting, clippy, publish-order/profile/platform/dispatch checks, plus uninstrumented Linux x86_64 and Windows x86_64 Rust tests and `onnx-genai-cli` build/test/e2e. Slow CI runs on push to `main`, nightly schedule, manual dispatch, and PRs carrying the `ci:full` label; it adds coverage uploads (`offline`, `mlas`, `cli-ort-linux`, `cli-ort-windows`), Windows ARM64, macOS arm64, CUDA compile lanes, and `audit`.
**Why:** Coverage instrumentation was the largest new cost (+9:06 on CLI Windows, +5:00 on Rust Windows, +3:11 on Windows ARM64) and has low marginal correctness signal on every PR. Windows x86_64 remains in the fast tier because Justin develops on Windows and recent contract coverage missed a Windows-only blind spot. Unit tests and CLI e2e remain on PRs because the missing CLI CI lane previously let bugs ship.
**Trigger decision:** Justin was away, so I chose the slow-tier triggers in his absence: merge to `main`, nightly, manual dispatch, and `ci:full` label on an open PR. He should revisit this if he wants a different slow-tier cadence.
