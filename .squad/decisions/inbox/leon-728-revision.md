### 2026-08-07: PR #728 C1 growing-symbol classifier — reviewer-rejection revision (Leon)
**By:** Leon
**What:** Closed the two findings Harry's re-review left open on the CUDA-graph-capture eligibility classifier for pointwise/elementwise/bitwise/prelu ops, keeping the 35B-A3B QMoE hybrid decode collapse at **154→34** captured segments. Cohaagen and Deckard are locked out of this artifact; this revision was produced independently from their code/reviews only.

**Chosen approach: canonicalized, EQUIVALENCE-CLASS-CLOSED growing DENYLIST (with CSA output-5 coverage), not a pinned allowlist.**

Rationale. The task strongly preferred a fail-safe pinned ALLOWLIST, but Deckard already implemented and measured it at **154→94** on 35B — the allowlist excludes benign *fresh* warm-decode-seeded symbols (Cast/Mul/QMoE/ScatterElements), dissolving ~60 segments of the collapse that is this PR's entire purpose. Recovering those toward 34 would require heuristically re-admitting fresh symbols, which is exactly the correctness risk the allowlist is meant to avoid. The task's explicit fallback — "ship the CANONICALIZED, equivalence-class-closed DENYLIST WITH CSA output-5 coverage … only if you can argue its growing-set is provably complete" — is the correct choice here, and I made it provably complete and transitively closed. Harry's re-review explicitly permits "union-find/equivalence-class canonicalization (or equivalent transitive propagation)."

**Finding 1 — downstream-consumer symbol aliasing (the hard one).** Shape inference replaces two distinct broadcast symbols with the lower-id representative (`context.rs::broadcast_dim` 468–482), so a growing KV symbol can be unified INTO a pinned-looking representative (`batch`) that a DOWNSTREAM pointwise op then copies onto BOTH its edges — escaping exact `SymbolId` membership. Deckard's input+output edge check only caught the *first* aliasing op, not its consumer.

Fix (`kernel_cache.rs::close_growing_under_symbol_unification`): I rebuild the SAME union-find shape inference builds implicitly. For every default-domain elementwise-broadcasting node (`op_broadcasts_elementwise`: Add/Sub/Mul/Div/Pow/Mod/BitShift/Bitwise\*/PRelu/comparisons/And/Or/Xor/Min/Max/Sum/Mean/Where — exactly the ops that call `InferenceContext::broadcast`), I right-align each input-shape pair and `union` the two symbols meeting at any axis (the `(Symbolic,Symbolic)` representative-substitution case). A class is then marked GROWING if ANY member is a collected growing symbol, and every member of a growing class is added to the set. Because `node_capture_seq_independent` still tests exact both-edge membership, the CLOSED set makes the growing property transitively correct: a consumer carrying only the representative is now rejected. Non-broadcasting ops (MatMul contraction, attention, reshape) are excluded so no spurious unification occurs. Over-inclusion is fail-safe (stays eager, never admits a growing op).

Canonicalization mechanism = a minimal hash-map union-find (`SymbolUnionFind`) over `SymbolId`, lower-id-as-root to mirror inference's representative rule (correctness is root-choice-independent). Membership is then plain exact-membership on the closed set — no per-call union-find, so `node_capture_seq_independent`, the `capture_growing_symbols` field, `build.rs`, and `dispatch.rs` are all UNCHANGED.

**Finding 2 — CSA ratio-4 output-5 `selections`.** `CompressedSparseAttention` mints a fresh, growing `selections` symbol on the LAST axis of output 5 (`[query[0], index_heads, query_seq, selections]`, `custom_ops.rs` 181–195); the penultimate scan covering outputs 1/3 missed it. Added `KvCacheSlots.last_axis_outputs = &[5]` for CSA and `last_axis_growing_symbol`, so the trailing `selections` axis is collected as growing. A pointwise op consuming output 5 now stays eager.
