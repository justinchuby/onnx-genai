### 2026-09-03: CUDA Einsum uses one universal device index program behind optional fast paths
**By:** Batty
**What:** Every schema-valid CUDA Einsum now has an immutable, exact-signature `CudaEinsumPlan`. GenericNative directly evaluates the canonical IR index program on device for arbitrary arity, strides, diagonals, broadcasts, output order, and reductions. Bounded exact-DP/greedy trees use reusable f32 intermediates for f16/BF16 and exact-width integer storage; eligible f32 binary steps use cuBLASLt, while the existing direct f16/f32 GEMM/BMM and zero-copy view paths remain. BF16 is admitted only by Einsum-28. The conformance corpus no longer requests float-only MatMul/cuBLAS routes for the integer-matmul case and now includes a 128-operand scalar case.
**Why:** CUDA placement must never turn a legal ONNX expression into CPU/ORT fallback. Fast-path eligibility is an optimization property, not a semantic support boundary; the universal device program is the bounded-memory fallback when layout, dtype, device capability, or planner workspace prevents a specialized route.
