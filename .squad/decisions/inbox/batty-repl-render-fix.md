### 2026-07-30: REPL live rendering must share reasoning state and coalesce frames
**By:** Batty
**What:** Reasoning-span detection now checks the chat template's rendered current generation prompt instead of scanning source text after the last `assistant` token. Streaming and final history-splitting both run through the same `ReasoningStream` marker state machine: it buffers possible partial delimiters, emits marker-split chunks for rendering, and `ReasoningMarkers::split` consumes the same events to decide `complete` and answer text. Live inline viewport row reservation now uses ratatui's own wrapped-line count rather than `ceil(total_width / width)`. The live viewport now mutates its line/segment buffer on every token but redraws only on a frame timer plus final flush, so terminal repaint cadence no longer blocks decode cadence.
**Why:** Qwen3's template mentions `<think>` for prior assistant messages and the `enable_thinking=false` branch, but the default current generation prompt does not open a reasoning span. Source scanning reported `opened_by_template=true` while the rendered prompt did not contain `<think>`. A single marker parser prevents streaming color and final `split.complete`/history decisions from disagreeing, including when `<think>` or `</think>` is split across tokens or `</think>` shares a token with answer text. Ratatui word-wrap can occupy more rows than a total-width ceiling, so under-reserving lets the inline viewport overwrite scrollback. Drawing a full ratatui frame for every token makes the terminal the decode bottleneck; coalescing frames keeps the inline viewport responsive while preserving every generated token in the buffer and scrollback.
