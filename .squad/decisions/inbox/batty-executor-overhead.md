# Batty executor overhead follow-up

- Scope: `crates/onnx-runtime-session` executor hot path only; did not touch CPU kernels or `mlas-sys`.
- Dispatch breakdown before: phase profiling showed `exec_kernel.node` ~870ms/96 decode steps, `exec_kernel.compute` ~788ms, leaving ~82ms node overhead (~0.85ms/token) plus setup ~0.16ms/token. Largest pieces: `build_inputs` ~23ms/96, `setup_total` ~16ms/96, `size_buffers` ~7ms/96, `resolve_soft` ~4.8ms/96, `get_kernel` ~7.4ms/36k calls (~0.2us/node).
- Change: defer `TensorView` construction until needed; skip materialization Vec allocation on already-contiguous inputs; keep output buffers resident in the map rather than remove/reinsert; mark load-time-shaped outputs as pre-sized so steady decode skips redundant output backing checks when buffers already exist.
- Dispatch breakdown after (phase profiler, 96 tokens): `exec_kernel.node` 957.1ms, `compute` 868.3ms, overhead ~88.8ms (~0.93ms/token) on a noisy run. Instrumented subspans: `build_inputs` 23.45ms, `resolve_outputs` 15.74ms, `get_kernel` 7.63ms, `output_bindings` 4.34ms, `build_views` 2.80ms, `output_strides` 2.78ms, `output_backings` 0.61ms over only 2880 calls. The micro-reductions are real in the subspans, but total dispatch remains dominated by input/binding bookkeeping and host contention.
- Qwen3 graph fusion audit: no `Add` nodes and no `Add -> SkipSimplifiedLayerNormalization` pattern. `SkipSimplifiedLayerNormalization` already owns residual/skip behavior, so Priority 3 has no applicable Qwen3 fusion.
- Per-op profile after: `Reshape` remains absent. Representative steady step: `MatMulNBits` ~8.0-9.8ms/197 calls, `GroupQueryAttention` ~0.52ms/28, norms ~0.25-0.33ms; shape metadata dispatch is gone.
- Benchmark (`profile_native --ep cpu --steady --runs 15 --tokens 96`, qwen3-0.6b, contended host): native best 106.47 tok/s, p90 106.16, median 100.99. ORT best 109.45 tok/s, p90 109.30, median 107.26. Honest gate: this runtime cleanup did not cross ORT on this run; residual gap is diffuse executor bookkeeping plus contention sensitivity, not a single obvious kernel-side lever.
- Validation: `cargo test -p onnx-runtime-session executor --quiet` and `cargo test -p onnx-genai-engine --features native-backend,mlas native_decode --quiet` passed.
