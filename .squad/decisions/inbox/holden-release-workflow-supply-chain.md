### 2026-07-27: Harden release workflow action provenance
**By:** Holden
**What:** Release workflows now avoid the personally-owned `dtolnay/rust-toolchain@stable` action. `publish.yml` replaced its four toolchain steps and `wheels.yml` replaced its two toolchain steps with direct `rustup toolchain install stable --profile minimal` plus `rustup default stable`, matching Pris's `ci/harden-and-coverage` pattern. `publish.yml` now serializes all publish runs under the workflow-level concurrency group, and `wheels.yml` gained the same no-cancel serialization.
**Why:** Release workflows hold crates.io/PyPI publishing authority, so personally-owned setup actions are higher-risk there than in ordinary CI. The direct `rustup` replacement preserves the previous stable/minimal/no-extra-targets toolchain state for every affected job; Linux cibuildwheel containers still use their existing `pyproject.toml` `before-all` Rust installation. `pypa/gh-action-pypi-publish` is deliberately kept because PyPA's trusted-publishing action uses OIDC and avoids long-lived PyPI credentials; replacing it with raw `twine` would likely worsen the supply-chain posture. `pypa/cibuildwheel` is deliberately kept as PyPA-owned wheel infrastructure. `codecov/codecov-action` is vendor-owned and is the upload endpoint, so it is acceptable to keep. Follow-up recommendation: pin all retained third-party actions, and ideally GitHub-owned actions too, to immutable commit SHAs with an update process; tag pins such as `release/v1`, `v4.1.0`, and `v4` are mutable.
