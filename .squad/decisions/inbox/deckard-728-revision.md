### 2026-08-07: PR #728 C1 growing-symbol classifier — reviewer-rejection revision
**By:** Deckard
**What:** Revised the build-time "growing-symbol" CUDA-graph-capture classifier to fix all three of Harry's blocking findings, keeping the 35B-A3B QMoE decode collapse at 154→34 captured segments.

**Finding 1 — symbol-representative aliasing.**
The classifier now applies the growing-symbol DENYLIST to BOTH an op's INPUTS and its OUTPUTS (previously outputs only). Broadcast/shape-inference can substitute a lower-id pinned representative (e.g. `batch`) on an aliasing op's OUTPUT, but the FIRST op in any such chain must still consume a tensor carrying the raw growing KV symbol on an INPUT. Rejecting any input that references a growing symbol keeps that op eager, closing the alias hole without a full union-find pass. (`node_capture_seq_independent`, kernel_cache.rs.)

**Finding 2 — incomplete growing-symbol coverage.**
Growing-symbol collection is no longer a 3-op allowlist. Two complementary sources are unioned: (a) recognized stateful attention ops — GQA / default `Attention` / `pkg.nxrt::IndexShare` / **`CompressedSparseAttention`** (CSA cache records on outputs[1]/[3]); and (b) a GENERIC scan of the model's DECLARED KV I/O — any graph input named `past…` / output named `present…` with a rank-4 `[batch, kv_heads, seq, head_dim]` layout and a symbolic penultimate axis. The rank-4 + symbolic-penultimate guard excludes fixed-capacity conv/recurrent (Mamba/GDN) states, so the GDN pointwise ops stay capturable. No per-model hardcoding. (`compute_capture_growing_symbols`, `attention_kv_cache_slots`, kernel_cache.rs.)

**Design note (allowlist vs denylist).** The task PREFERRED a fail-safe pinned ALLOWLIST (capture-eligible iff every symbolic dim is provably pinned). I implemented and measured it: it collapses to **94** captured segments on 35B (vs 34), because warm-decode seeding legitimately folds benign FRESH (non-growing, non-pinned) output symbols on Cast/Mul/QMoE/ScatterElements into captured segments, and the allowlist excludes them — dissolving the collapse that is this PR's entire purpose. I therefore took Harry's explicit accepted MINIMUM (the fallback): a growing DENYLIST applied to both input and output edges, with growing derivation extended to CSA + generic declared KV I/O. This turns findings 1 & 2 from "silent corruption" into "at worst stays eager, never wrong" while preserving 34 segments. True build-time union-find canonicalization was NOT implemented; the input-side denylist is the practical defense against representative aliasing.

**Finding 3 — permissive oracle tripwire.**
The re-anchored `qwen36_35b_a3b_qmoe_divergence` test kept the fp32-teacher-forcing capture-independent PRIMARY lock (@119 == 33803), but its autoregressive check was a non-fatal eprintln accepting any token. Restored a real, FATAL regression tripwire: `assert!(t == ORACLE_TOKEN (33803) || t == C1_CAPTURE_TOKEN (46283))` — the two known-benign fp16-tie outcomes of the documented #722 coin-flip. Any OTHER token (dense outlier 5342, reused-state 279, or unrelated = genuine captured-decode corruption) now FAILS CI. The intended C1 outcome (46283) is confirmed in the allowed set; documentation eprintln retained.

**Validation (all pass):**
- Oracle test `qwen36_35b_a3b_qmoe_divergence` (release): capture ON (ONNX_GENAI_CUDA_GRAPH=1) 2 passed / 795s; capture OFF (=0) 2 passed / 822s. fp32-oracle argmax @119 == 33803 (margin +0.0908 in band), dense int4 CUDA teacher-forced == 33803 (+0.078), autoregressive tripwire token == 46283 (allowed).
- 35B-A3B QMoE (CUDA_VISIBLE_DEVICES=0 taskset -c 1, KV_MAX_LEN=4096, profile_native --steady --warmups 2 --runs 3 --tokens 128 --decode-skip 8 -t0): **34 captured segments / 33 eager seams** (unchanged from baseline d447aa20's 34), median **83.11 tok/s** (baseline 83.75, within run-to-run noise); GDN pointwise stayed capturable (growing set = 11 KV symbols, none pinned).
- qwen2.5-0.5b-int4 pure-GQA byte-exact: capture ON == OFF, 64 identical decode tokens.
- Unit tests (onnx-runtime-session, cuda): 5 pass — growing classifier admits pinned & rejects growing+aliased op; CSA cache-record op eager; generic declared `present.*` rank-4 KV op eager; benign fresh symbol stays capturable (collapse-preserving); recurrent state contributes no growing symbol.
- `cargo fmt --all --check` clean; `cargo clippy` on onnx-runtime-session (cuda) and onnx-genai-engine (native-backend,cuda tests) clean.

**Why:** A denylist that misses one growing symbol silently corrupts decode. Extending it to both op edges + CSA + a generic declared-KV-I/O scan makes the miss modes (aliasing, CSA, unrecognized attention) degrade to lost perf, never wrong, while the whole-op growing check preserves the 34-segment collapse and its ~4% tok/s. The oracle tripwire regains teeth against real capture corruption without re-pinning to the benign fp16 coin-flip.
