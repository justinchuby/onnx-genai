perf(ort): recover the allocation size from a header, not a side table

Answers the open question on #596: the governed allocator can be on by
default, but not as it was written.

The first version kept a `HashMap<address, (layout, lease)>` because ORT's
`Free` hands back only a pointer and the size has to come from somewhere.
That cost a lock and a hash on **both** paths. Measured, it -- not the lease
and not `malloc` -- was the dominant cost of governing an allocation.

Numbers on this machine, release build, alloc+free of decode-shaped sizes,
best of five alternating rounds:

    design                        cheap governor   bookkeeping governor
    per-request + side table          18.0 ns            30.9 ns
    header, no pooling                15.2 ns            30.3 ns
    bulk-leasing arena                31.5 ns            31.3 ns

I built the arena first, on the assumption that per-request governance was
too expensive to default on. It was not: an arena on host memory adds a lock
of its own in place of the governor's, and `malloc` already pools with
per-thread caches, so there was nothing left to win. The arena lost on both
governors and is not in this change.

What is left is the header: one alignment unit before each block holding the
total size. No lock, no hash, no table. The header is charged to the
governor, because it is memory the process really takes -- charging only the
requested size would understate the budget by 64 bytes on every allocation.

`live_bytes` and `live_count` become relaxed atomics. They are observability;
the governor's books stay authoritative.

The allocator now takes `Arc<dyn LeaseAccounting>` rather than
`Arc<dyn MemoryGovernor>`. It releases by size at free time instead of
holding a `MemoryLease` per block -- holding one would mean keeping the table
this change removes. G2 is preserved structurally: exactly one release per
free, and the header is consumed with the block.

One thing this gives up: a foreign pointer is no longer detected. The side
table could refuse an address it never handed out; a header cannot. Freeing a
pointer this allocator did not return was already undefined, and ORT only
frees what it was given.
